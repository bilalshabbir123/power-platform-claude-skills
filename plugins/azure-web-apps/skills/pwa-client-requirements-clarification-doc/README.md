# pwa-client-requirements-clarification-doc

**Problem it solves:** going from discovery/demo transcripts to a proposal without the client ever confirming who sees what, so scope is argued later.

**Use it when:** after a discovery call or demo, you need a client-facing document listing roles, screens, features per role and high-level mock screens, for the client to comment on before the proposal.

**What's inside:** document structure, screen × role matrix with Full/View/Own/—, branded mock screens built as HTML and captured with Playwright, questions table with suggested answers, governance (client files never committed), mistakes, checklist.

**Related skills:** `pwa-offline-first-sync`, `entra-id-msal-pwa-sign-in`, `azure-low-cost-poc-hosting`
